# Визуальный код

Закрытое исследовательское приложение. Локальный seed содержит 494 исторические записи; рабочий корпус строится детерминированно как 492 записи с сохранением истории ORCA и ИСКРА. Оригиналы лежат в `public/logos` только для локальной демонстрации; в подключённой версии они импортируются в private Supabase Storage.

## Локальный запуск

```bash
npm install
npm run import:verify
npm test
npm run build
npm run dev
```

## Подключение облака

1. Создать бесплатный Supabase project и выполнить SQL из `supabase/migrations` по порядку.
2. Создать первого пользователя вручную в Auth, затем добавить строку `profiles` с ролью `owner`. Открытая регистрация остаётся выключенной.
3. Скопировать `.env.example` в `.env.local`, указав URL и anon key. Service-role key в клиент не добавлять.
4. Импортировать исходники в private bucket `logos` административным локальным скриптом и загрузить нормализованные записи.
5. В Cloudflare Pages: build command `npm run build`, output `dist`, переменные только `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

## Экспорт и восстановление

Полная резервная копия состоит из `pg_dump` базы, выгрузки private bucket и manifest с SHA-256. Восстановление выполняется в новый Supabase project: миграции → `pg_restore` → загрузка файлов → сверка manifest. Проверять минимум количество 494 исторических / 492 активных записей и все SHA-256.

## Ограничения первой сборки

Интерфейс, seed, схема, RLS, Supabase Auth и базовые расчёты реализованы локально. Без переменных Supabase приложение явно показывает локальный демонстрационный режим; с переменными доступ закрывается настоящим входом по email и паролю. Storage/БД включаются после создания Supabase project. Автоматический пиксельный алгоритм старой цветовой разметки не заявлен восстановленным; тип и образ подтверждаются человеком.
